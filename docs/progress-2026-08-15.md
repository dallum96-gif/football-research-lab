## Identity / aggregation contract

- Persistent player identity is canonical full player name, normalised across schema generations.
- Seasonal source IDs (`player_code`, `element`, etc.) are aliases, not longitudinal identity.
- Multi-season totals are pooled from underlying seasonal rows.
- Per-90 metrics are calculated from pooled totals and pooled minutes.
- Ambiguous player identities are not silently merged.
- V0.1 provenance fields remain supported, including `source_file` and `source_rows`.

## Risk Strategy Framework

1. Preserve the validated data/research layer.
2. Keep a known-good rollback copy before GUI migrations.
3. Prefer isolated page/module changes over bulk rewriting of monolithic `app.py`.
4. Compile candidate code before replacing trusted files.
5. Use the fast regression gate for UI-only work; run the full 26/26 gate after research-engine changes or before release.
6. Do not silently stage abandoned UI experiments into a release commit.
